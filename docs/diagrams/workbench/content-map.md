# Workbench 图文与表达形式

v3，2026-10-29。先判断内容要解释的关系，再决定是否画图及采用何种形式。当前是七组双语图、一组双语文字对照表，以及工程规约列表；不要求每篇或每节的图数相同。

| 位置 | 表达形式 | 直接回答的问题与边界 |
| --- | --- | --- |
| Environment：导读后、第一个配置小节前 | `environment-toolkit` 职责分支 | 人定义什么，Agent 组织什么，模型／工具／运行环境／规约各做什么？是全文总览，不是 Node.js / Python 配置图。 |
| Environment：第 4 节工具接入说明后、推荐前 | `environment-mcp` 接入拓扑 | Host 内多个 Client 如何连接对应的 Server，并接入文档、网页和浏览器？三个例子对应后文工具，不暗示必须同时安装。 |
| Environment：第 6 节工程纪律 | 文字规则与执行说明 | 范围、计划与技术约束已用三条列表明确。删除重复流程图，保留原规约和检查要求。 |
| Scope：第 1 节路径导读后 | `scope-paths` 双路径合流 | 已有框架和模糊想法分别怎样开始，最终汇入什么共同问题？两条路径可以互补。 |
| Scope：第 4 节最短完整流程的案例目标后 | `scope-mvp` 连续旅程 | 单次练习最短但完整的价值流程是什么？材料、出题、作答反馈、回顾不可只保留孤立功能；不是所有产品的固定 MVP。 |
| Scope：第 5 节“分开检查功能完成与用户价值” | 可选择的文字对照表 | 对照问题、案例、依据与结论边界。删除两栏卡片图片和重复说明，不把功能通过当成价值成立。 |
| Architecture：第 2 节选型导读后 | `architecture-decisions` 判断与回路 | 从产品约束比较候选，核实关键假设；适配则记录，不适配则修订。不是技术栈排名。 |
| Architecture：第 3 节假设练习案例引入后 | `architecture-boundaries` 可信边界 | 哪些处理必须在可信服务端，谁保存密钥，外部生成结果怎样回到校验？职责边界不代表微服务拆分。 |
| Architecture：第 5 节失败处理说明后 | `architecture-failures` 时序与替代结果 | 同步生成成功与失败分别怎样返回？保留输入、显式重试；超时不等于取消上游工作。 |

MCP 角色关系沿用 [官方架构说明](https://modelcontextprotocol.io/docs/learn/architecture)。其他案例均为原文的假设设计，不添加实际产品数据、数量和性能结论。

发布核对六份正文的章节、图注和上下文；所有提示词和 fenced blocks 保持一致。图像本地检查之外还回读 CMS 与公开页面；实际页面视觉巡检仍受 Work 浏览器设置限制。
